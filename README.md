## Client: Bharat Logistics

Bharat Logistics, a leading last-mile delivery service in India, is grappling with unpredictable daily parcel volumes across its numerous delivery hubs. This unpredictability leads to significant inefficiencies in allocating delivery vehicles, staff, and managing warehouse space. They require a simple, data-driven solution to forecast these volumes more accurately, enabling better resource planning and cost optimization.

**Sprint goal:** Develop a foundational system to predict daily parcel volumes for delivery hubs using historical data.

# Interfaces

## 1. Data Processing Output (CSV File)

`data_preprocessing/main.py` will read `raw_data.csv` and output a cleaned, processed CSV file named `processed_data.csv` into the `prediction_api/` folder.

**File:** `prediction_api/processed_data.csv`

**Columns:**
- `delivery_date`: Date of delivery (YYYY-MM-DD string)
- `hub_id`: Unique identifier for the delivery hub (string, e.g., 'DEL001', 'MUM002')
- `parcel_volume`: Total number of parcels for that hub on that date (integer)

**Example `processed_data.csv` entry:**
```csv
delivery_date,hub_id,parcel_volume
2023-10-01,DEL001,1200
2023-10-01,MUM002,850
2023-10-02,DEL001,1350
```

## 2. Prediction API Endpoint

`prediction_api/app.py` will expose a single POST endpoint for making parcel volume predictions.

**Endpoint:** `/predict` (POST request)

**Request Body (JSON):**
```json
{
    "hub_id": "DEL001",
    "date": "2023-10-27" 
}
```
- `hub_id`: The ID of the delivery hub for which to predict.
- `date`: The target date for the prediction in YYYY-MM-DD format.

**Response Body (JSON):**
```json
{
    "hub_id": "DEL001",
    "date": "2023-10-27",
    "predicted_volume": 1500 
}
```
- `hub_id`: The requested hub ID.
- `date`: The requested prediction date.
- `predicted_volume`: The predicted integer parcel volume for the given hub and date.

# How to Run the Product

1.  **Set up virtual environments:** Create and activate a Python virtual environment in both `data_preprocessing/` and `prediction_api/` directories.
2.  **Install dependencies:** In each part's directory, install dependencies (e.g., `pip install -r requirements.txt`).
3.  **Run Data Preprocessing:** Navigate to `data_preprocessing/` and execute `python main.py`. This will generate `processed_data.csv` in the `prediction_api/` directory.
4.  **Run Prediction API:** Navigate to `prediction_api/` and execute `python app.py`. This will start the Flask/FastAPI server, making the `/predict` endpoint available locally (e.g., `http://127.0.0.1:5000/predict`).
5.  **Test the API:** Use a tool like `curl` or Postman to send a POST request to the `/predict` endpoint.
6.  **Integration (SHREE):** The integration owner will merge PRs, ensure end-to-end functionality, update `integration/README.md` with comprehensive run steps, and deploy the `prediction_api` (e.g., to Render or Streamlit Cloud) with the `processed_data.csv` generated by Manikanta's script. The deployment link will be added to the README.
